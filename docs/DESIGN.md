# 每日任务清单 · 产品设计文档（MVP）

> 版本：v0.1（MVP） ｜ 状态：设计中

## 1. 产品定位
一个轻量的个人命令行待办工具，帮助用户在电脑端记录、跟踪并完成每日任务。
MVP 阶段聚焦「最小可用闭环」，后续再迭代「每日」语义与高级能力。

## 2. 整体方向
- 终端 / 命令行优先，单机本地使用
- Python 实现，零或极少第三方依赖
- 数据本地持久化，不联网、不云同步
- 小步快跑：先跑通核心闭环，再逐步加日期、标签、提醒等

## 3. 目标用户与使用场景
- 在校学生 / 开发者，习惯命令行与 Git 工作流
- 典型场景：每天开始前列出当日任务 → 过程中勾掉已完成项 → 随时增删修正

## 4. MVP 功能范围（主要功能）
以 `task` 为命令入口：
- **add**：`task add "任务内容"` —— 新增一条待办
- **list**：`task list` —— 列出全部任务，显示序号与状态（`[ ]` 未完成 / `[x]` 已完成）
- **done**：`task done <id>` —— 将指定任务标记为完成
- **rm**：`task rm <id>` —— 删除指定任务

持久化：本地 JSON 文件（如 `tasks.json`），每条任务含 `id` / `内容` / `完成状态`。

> 说明：MVP **不做日期 / 每日视图**，所有任务在同一个扁平清单中管理；「每日」维度留待 v1.1。

## 5. 暂不做（后续迭代）
- 日期字段、今日视图、未完成项跨天顺延
- 编辑任务内容、优先级 / 标签 / 分类
- 提醒与通知、统计与历史
- 图形界面 / 手机端 / 多端同步

## 6. 技术选型
- 语言：Python 3（当前环境已具备）
- 命令解析：`argparse`
- 存储：`tasks.json`（JSON 文件），MVP 阶段不引入数据库
- 结构：存储层与命令逻辑分离，便于单元测试

## 7. 质量与验收（遵循 AGENTS.md）
- 每次改动完成后必须创建对应 Git commit，便于追踪与回滚
- 每次改动后编写 / 更新相关测试，交付前确保所有测试通过
- MVP 测试覆盖：`add` / `list` / `done` / `rm` 的存储与状态逻辑（单测）+ 一条命令行冒烟测试

## 8. 版本路线
- **v0.1 MVP**：`add` / `list` / `done` / `rm` + JSON 持久化
- **v1.1**：加入 `date`、今日视图、未完成项跨天顺延
- **v2+**：标签 / 优先级、提醒、统计、GUI / 同步（待定）
