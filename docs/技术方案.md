# 每日任务清单 · 技术方案（v0.1 MVP）

> 关联文档：`docs/DESIGN.md`（产品设计 / 需求）
> 技术栈状态：已锁定 —— 本地网页应用 · Python 标准库后端（零依赖）· HTML/CSS/JS 前端 · 本地 `tasks.json` · 导出/导入双备份

## 1. 目标与范围
按 `DESIGN.md` 的 v0.1 实现最小可用闭环：网页界面完成 **add / list / done / rm**，数据自动存本地 `tasks.json`，并提供**导出 / 导入**做备份。不实现日期、标签、提醒、同步。

## 2. 总体架构
```
┌──────────────┐   HTTP (fetch)   ┌────────────────────┐   读写    ┌──────────────┐
│  浏览器前端   │ ───────────────▶ │  Python 后端        │ ───────▶ │ tasks.json   │
│ static/index  │ ◀─────────────── │  (http.server, 零依赖)│ ◀─────── │ (本地文件)   │
└──────────────┘   返回 JSON/HTML  └────────────────────┘           └──────────────┘
```
- 前端只跑在浏览器里，所有数据操作都通过后端接口完成。
- 后端仅监听 `127.0.0.1`（本机），不对外暴露。

## 4. 后端技术方案
### 4.1 技术选型
- Python 3 标准库：`http.server`（服务 + 路由）、`json`（序列化）、`threading`（可选 `ThreadingHTTPServer` 提升并发）。
- **不引入任何第三方库**，保证「只装 Python 就能跑」。

### 4.2 接口设计（同源 REST 风格）
| 方法 | 路径 | 说明 | 请求体 / 参数 | 返回 |
|------|------|------|---------------|------|
| GET  | `/`            | 返回前端页面 `static/index.html` | — | HTML |
| GET  | `/api/tasks`   | 列出全部任务 | — | `{tasks:[...]}` |
| POST | `/api/tasks`   | 新增任务 | `{content:"..."}` | 新建的任务对象 |
| POST | `/api/tasks/{id}/toggle` | 切换完成状态 | 路径 id | 更新后的任务对象 |
| DELETE | `/api/tasks/{id}` | 删除任务 | 路径 id | `{ok:true}` |
| GET  | `/api/export`  | 导出为 json 文件下载 | — | `tasks.json` 附件 |
| POST | `/api/import`  | 从上传的 json 覆盖导入 | 文件 | `{ok:true, count:n}` |

> 说明：`{id}` 为任务数字编号；非法 id / 空内容返回 4xx + 错误信息。

### 4.3 存储层设计
- `tasks.json` 结构：`[{"id":1,"content":"...","done":false}, ...]`
- 启动时若文件不存在则初始化为空列表；每次写操作后**原子写**（先写临时文件再替换）避免半截文件。
- 新任务 `id` = 当前最大 id + 1（空列表时从 1 开始）。
- 将「读写 JSON / 增删改」抽成纯函数（如 `load_tasks(path)`、`add_task(tasks, content)`），**不依赖 socket**，方便单测。

### 4.4 关键实现点
- 路由：用 `BaseHTTPRequestHandler`，在 `do_GET/do_POST/do_DELETE` 中按 `path` 分发；把「业务逻辑」与「HTTP 处理」分离，使逻辑可测。
- 请求体读取：`Content-Length` + `rfile.read`；JSON 用 `json.loads`。
- 响应：统一 `application/json`（接口）或 `text/html`（页面），设置正确 `Content-Type`。
- 端口：默认 `8000`，可用环境变量 `PORT` 覆盖；绑定 `127.0.0.1`。

## 5. 前端技术方案
### 5.1 界面
- 直接复用 `demo/index2.html` 的米色 UI（标题居中、输入区在下、暖色调），把「内存假数据」改为「调接口拿真数据」。

### 5.2 与后端交互
- `add`：读取输入框 → `POST /api/tasks` → 重新 `GET /api/tasks` 渲染。
- `list`：进入页面 `GET /api/tasks` 渲染列表 + 统计「共 N · 已完成 M」。
- `done`：点方框 → `POST /api/tasks/{id}/toggle` → 重渲染。
- `rm`：点删除 → `DELETE /api/tasks/{id}` → 重渲染。
- 渲染时对 `content` 做 HTML 转义，防止 XSS。

### 5.3 导出 / 导入
- 导出：`<a href="/api/export" download="tasks.json">` 触发下载。
- 导入：`<input type="file">` 选 json → `POST /api/import` → 成功后刷新列表。

## 6. 数据模型（tasks.json 示例）
```json
[
  {"id": 1, "content": "复习 STM32 定时器", "done": false},
  {"id": 2, "content": "写操作系统实验报告", "done": true},
  {"id": 3, "content": "健身 30 分钟", "done": false}
]
```

## 7. 测试方案（遵循 AGENTS.md）
- **存储层单测**（不启服务）：临时 `tasks.json`，覆盖 `add` / `toggle` / `delete` / 空列表初始化 / `export→import` 往返一致。
- **接口单测**：把路由逻辑包成可调用函数，用 `unittest.mock` 模拟请求/响应；或起 `ThreadingHTTPServer` + `urllib` 实跑关键路径。
- **冒烟测试**：脚本启动 `app.py`，依次 `add → list → toggle → delete → export`，断言状态码与数据正确，最后关服务。
- 交付前 `python -m unittest` 全绿方可提交。

## 8. 运行与部署（本机）
- 开发/使用：终端 `python app.py` → 浏览器开 `http://localhost:8000`。
- 日常：双击 `start.bat`（内部 `python app.py`，可加 `--open` 自动开浏览器）。
- 关闭：Ctrl+C 或关终端；数据已写入 `tasks.json`，不丢。

## 9. 安全与边界
- 仅监听 `127.0.0.1`，不对外网开放；单用户本地使用，**不做登录鉴权**。
- 输入校验：任务内容非空、长度上限（如 500 字）；前端转义防 XSS。
- `import` 仅接受合法任务数组，忽略多余字段，防止脏数据。

## 10. 风险与待确认
- `http.server` 为轻量服务，单用户足够；若以后要多标签页并发写入，可切 `ThreadingHTTPServer`（同为标准库）。
- 数据文件 `tasks.json` 建议加入 `.gitignore`，避免把个人清单提交进仓库。
- 跨天「每日」语义、标签、提醒等按计划留到 v1.1 / v2+，不在本次实现。
